# 自定义小骑士（CustomKnight）—— 加载失败修复说明

- **产物**：`D:\KDQSHH\Mods\CustomKnight（自定义小骑士）\CustomKnight.dll`
- **MD5**：`0665e5fada4a3cf213d6da792ba26256`（5392896 字节）
- **版本**：3.5.0（与原版一致，仅修复健壮性，**未改动任何汉化文本与功能逻辑**）

---

## 一、故障现象

启动游戏后模组加载阶段报错，**自定义小骑士整个模组加载失败**：

```
[CustomKnight] - 正在初始化 自定义小骑士 3.5.0.0-528d41
[CustomKnight] - 发现 162 个可替换部件（Skinables）
[CustomKnight] - Trying to apply skin xxx : on save slot 0
[ERROR]:[API] - Failed to load Mod `自定义小骑士`
[ERROR]:[API] - UnityEngine.UnityException: Texture '' is not configured correctly to allow GetPixels
   at Satchel.TextureUtils.GetCropped (Texture2D original, Rect region)
   at CustomKnight.NewUI.UIController.GetSkinIcon (ISelectableSkin skin)   ← 第 159 行
   at CustomKnight.NewUI.UIController.CreateUpdateGUI ()
   at CustomKnight.NewUI.UIController.GenerateMenu ()
   at CustomKnight.NewUI.UIController.EnableMenu ()
   at CustomKnight.CustomKnight.Initialize ()
```

## 二、原因

`UIController.GetSkinIcon` 生成皮肤列表图标时，会从皮肤的大图 `knight.png` 里裁剪一块：

```csharp
var tex = skin.GetTexture(knight).GetCropped(new Rect(2802f, 4096f - 3155f, 86f, 120f));
```

而 `StaticSkin.GetTexture` 的实现是：

```csharp
texture = new Texture2D(2, 2, TextureFormat.RGBA32, false);
texture.LoadImage(texBytes);        // 失败会抛异常 → 被 catch → 纹理仍是 2×2 的空图
```

于是只要某一张 `knight.png` **读取或解码失败**（或者尺寸不足），
`GetPixels(2802, 941, 86, 120)` 就会抛 `UnityException`。

**而这个异常没有任何保护** —— 它会一路冒泡到 `CustomKnight.Initialize`，
使整个模组加载失败：**皮肤菜单、换肤功能全部不可用**。

> 注意：这与"哪个皮肤被选中"无关。只要**目录里存在**一张有问题的 `knight.png`，
> 生成图标时遍历到它就会崩，因此表现为"整个模组都坏了"。

## 三、修复内容

给这处裁剪加上保护：

1. **先检查**：纹理存在、且尺寸不小于裁剪所需的最小尺寸（2888 × 1061）；
2. **失败时跳过裁剪**，退回到原代码已有的兜底返回值（不使用裁剪图标），而不是让整个模组崩溃；
3. **把出问题的皮肤写进日志**，便于定位：

```
[图标生成] 皮肤「xxx」的 knight.png 不可用（读取失败 / 512x512），已跳过裁剪
[图标生成] 皮肤「xxx」生成图标时出错，已跳过：<异常信息>
```

**除此之外没有改动任何其它逻辑**：汉化文本、皮肤切换、长椅检测、随机算法全部保持原样。

## 五、后续

若日志中出现 `[图标生成] 皮肤「xxx」...` 这样的行，
说明那个皮肤的 `knight.png` 确实有问题（读取失败或尺寸不足）。
届时可以：

- 把该皮肤目录移出 `Skins`，或
- 用图片工具把它另存为标准的 8 位 RGBA PNG（尺寸不小于 4096×4096 最稳妥）。

**但这不再影响模组加载** —— 修复后只是那一张皮肤没有自定义图标，其它一切照常。

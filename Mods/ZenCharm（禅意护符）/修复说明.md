## 一、修复的崩溃

日志里的这个异常：

```
NullReferenceException: Object reference not set to an instance of an object
  at ZenCharm.ZenCharm+<>c__DisplayClass20_0.<SetupJoniHealthFSM>b__0 ()
  at SFCore.Utils.MethodAction.OnEnter ()
  at HutongGames.PlayMaker.FsmState.ActivateActions ()
```

### 原因

模组用以下方式给两个状态机"换了动作"：

```csharp
var oldAction = joniHealthFsm.GetAction<PlayerDataBoolTest>("Check", 0);
var action = new MethodAction {
    method = () => {
        oldAction.Fsm.Event(oldAction.isTrue);    // ← 通过**已被换出状态的原动作**取 FSM
        ...
    }
};
check.Actions[0] = action;                        // ← 原动作就此离开状态
```

**原动作一旦被替换出状态，它就不再持有有效的状态机引用**，lambda 里再访问 `oldAction.Fsm`
就会抛空引用。这属于"延迟到运行时才爆炸"的写法。

### 修复（两处，`SetupCharmFSM` 与 `SetupJoniHealthFSM` 都有）

1. **改为直接捕获状态机与事件**，不再经由原动作：
   ```csharp
   var fsm = joniHealthFsm.Fsm;
   var trueEvent = oldAction.isTrue;
   var falseEvent = oldAction.isFalse;
   ...
   fsm.Event(trueEvent);
   ```
2. **补上一次性守卫**：`SetupJoniHealthFSM` 原本**没有**守卫，每次场景加载都会重复包装一次；
   而第二次取原动作时它已经不存在，`GetAction` 返回 null —— 这正是日志里第 3、5 次场景加载
   才报错的原因。现在加了 `JoniFsmSetup` 标志，并在返回主菜单 / 卸载时重置。
3. 顺带修正：`SetupCharmFSM` 也加了 `oldAction == null` 的提前返回；
   `SetupJoniHealthFSM` 的异常不再被静默吞掉（改为记录错误日志）。

模组显示名（`禅意护符`）与菜单说明此前已汉化；剩下两句是 `Logger` 调试/错误日志

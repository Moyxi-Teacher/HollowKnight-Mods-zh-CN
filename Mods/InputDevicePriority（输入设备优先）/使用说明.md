## 功能一：菜单光标不再被鼠标抢走

### 问题

在模组菜单里用手柄操作时，光标会被鼠标抢走，只能改用鼠标。

### 根因（从游戏代码确认）

1. UI 菜单的鼠标输入开关 `HollowKnightInputModule.allowMouseInput` 默认 **true**；
2. 游戏里虽然有 `InputHandler.StopMouseInput()` 和 `EnableMouseInput()`，
   但它们在整个 `Assembly-CSharp` 里**一次都没有被调用过** ——
   **游戏从来没有真正关闭过鼠标输入**；
3. 输入模块判断"鼠标在用"的条件是：

   ```csharp
   private bool MouseHasMoved => (thisMousePosition - lastMousePosition).sqrMagnitude > 0f;
   ```

   阈值为 `> 0f` —— **哪怕 0.0001 像素的抖动都算"鼠标在动"**。

### 解决办法

在菜单里按"最后使用的设备"开关鼠标输入：

| 你的操作 | 结果 |
|---|---|
| 手柄 / 键盘方向有输入 | **关闭鼠标输入** → 光标稳稳跟着手柄 |
| 鼠标真正移动（超过 4 像素）或点击 | **打开鼠标输入** → 鼠标照常可用 |
| 没接手柄 | **完全不干预** → 纯鼠标玩家不受影响 |

**放下手柄去拿鼠标，鼠标立刻就能用；手一碰手柄，鼠标自动让位。**

## 功能二：长列表跟着光标自动滚动

### 问题

模组列表很长时，手柄把光标往下移，**列表不会跟着滚动**，
光标跑出可视区后就看不到、也选不到后面的模组了。

### 根因（从游戏代码确认）

模组列表用的是滚动面板，官方给每个列表项挂了 `ScrollPaneSelector`，
想在"被选中时把该项滚进可视区"，但它有两个问题：

1. **只在方向导航事件时才执行**：

   ```csharp
   public void OnSelect(BaseEventData eventData)
   {
       if (eventData is AxisEventData)   // 其它来源的选中一律不滚动
       {
           ...
       }
   }
   ```

2. **那套位置换算公式与实际滚动模型对不上**，而且中间有一行算出来的结果
   被整个丢弃（反编译后可见），实际得到的 `Scrollbar.value` 无法正确对应滚动位置。

### 解决办法

改成"**选中项一变，就把它滚进可视区**"，位置直接按滚动模型反推，不再依赖官方公式：

```csharp
// 滚动模型（来自游戏的滚动面板实现）：
//   pane.anchoredPosition.y = (内容高 - 可视高) * scrollbar.value
// 所以要让内容滚到 offset 处：
bar.value = offset / (内容高 - 可视高);
```

只在**选中项发生变化**时调整一次，不会每帧覆盖滚动条，也不影响手动拖动滚动条。
上下各留 12 像素边距，免得选中项贴着边缘。

> 顺带的好处：用鼠标点击列表项时同样会跟随滚动（原来也不会）。

## 一、完整根因链（终于闭合）

```
Konpanion 克隆小骑士对象
   ↓  UnityEngine.Object.Instantiate(GameObject)
触发被克隆对象上所有 PlayMakerFSM 的 OnAfterDeserialize
   ↓
Fsm.InitData() → FsmState.LoadActions() → ActionData.CreateAction()
   ↓  用 Activator.CreateInstance 反射实例化每个动作类型
遇到 Vasi.InvokeMethod —— 它**没有公开的无参构造函数**
   ↓
MissingMethodException: Default constructor not found for type Vasi.InvokeMethod
   ↓
克隆 / 反序列化过程被打断 → 场景对英雄的跨场景引用解析错乱
   ↓
长椅状态机的 Hero 变量被解析成伙伴克隆体 kompanion
   ↓
「Can Rest?」取不到 HeroController 组件 → CallMethodProper 静默返回 → 长椅失效
```

日志中的直接证据（堆栈自下而上）：


**这也解释了为什么之前所有排查都指向"Konpanion 克隆"却始终修不干净** ——
克隆本身只是**触发器**，真正让过程崩掉的是 `Vasi.InvokeMethod`。

## 二、修复内容

给 `Vasi.InvokeMethod` 补上 PlayMaker 反射实例化所要求的**公开无参构造函数**，
并把调用改为空值安全：

```csharp
public class InvokeMethod : FsmStateAction
{
    private readonly Action? _action;

    // PlayMaker 通过反射实例化 FsmStateAction，要求存在公开的无参构造函数
    public InvokeMethod() { _action = null; }
    public InvokeMethod(Action a) { _action = a; }

    public override void OnEnter()
    {
        _action?.Invoke();   // 空值安全
        Finish();
    }
}
```

（这段修复此前已写入仓库源码 —— 与 Tasks #70 中对 FiveKnights 同类问题的处理一致 ——
但**从未编译部署到游戏**；游戏里装的一直是缺少无参构造的旧版。）

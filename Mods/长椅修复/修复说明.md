## 二、只剩一条路：目标对象在动作执行时取不到

`CallMethodProper.OnEnter()` 的结构是：

```csharp
public override void OnEnter() {
    parametersArray = new object[parameters.Length];
    DoMethodCall();
    Finish();                       // ← 无论成功失败都会调用
}
```

所以"Finish 被调用"只能说明动作跑了，**不能说明方法被调用**。

而 `DoMethodCall()` 里所有可能失败的路径中，**只有一条既无日志、又不报错的**：

```csharp
GameObject ownerDefaultTarget = base.Fsm.GetOwnerDefaultTarget(gameObject);
if (ownerDefaultTarget == null) return;        // ← 静默返回，什么都不做

// 其余路径都会留下痕迹：
//   behaviour 为空      → 无日志（但审计显示 behaviour="HeroController"，非空）
//   component 取不到    → LogWarning("...missing behaviour...")   ← 日志里没有
//   方法名无效          → Debug.LogError(...)                     ← 日志里没有
//   调用抛异常          → Debug.LogError("CallMethodProper error") ← 日志里没有
```

**⇒ 结论：动作执行的那一刻，`GetOwnerDefaultTarget()` 返回了 null。**

**但我在状态机启用时做过审计，当时读到的是 `Knight`（正常）。**
**⇒ 说明这个引用值在"审计之后、动作执行之前"被重置了。**

## 三、v14 做什么

**1. 在动作执行前的那一刻修正引用（核心）**

挂钩 `FsmState.OnEnter`，在 `orig(self)` **之前**（PlayMaker 的执行顺序是：
先 `OnEnter`，随后才逐个执行动作）把该状态内**目标确定为英雄**的引用重新指向当前英雄。

- 只写 `FsmOwnerDefault.GameObject.Value` 这个字段（动作运行时读的就是它）；
- 每次修正都会记录**原字段值**与 `UseVariable` 取值；
- 只改引用，不碰玩家状态。

**2. 目标解析追踪**

在每个动作完成时打印**动作执行那一刻**目标的真实解析结果：

```
⤷ 目标解析：OwnerOption=SpecifyGameObject UseVariable=True 字段值=null → GetOwnerDefaultTarget=null
```

这一行会直接给出答案：到底是字段被重置成 null，还是解析机制另有问题。
